# 연말 법 개정 반영 절차 (매년 12월)

세율·감면·연납 공제는 연말 국회에서 고친 지방세 관계법이 다음 해 1월 1일부터 적용되는 일이 많다. 이 사이트는 2027년 값을 **2026-11-01 현행법 기준**으로 넣어 두었으므로, 12월에 개정 여부를 확인하고 반영한다.

## 1. 일정 (2026년)

| 시기 | 할 일 | 누가 |
|---|---|---|
| 12/1 | 영향 지도 갱신: `node scripts/law-impact.mjs --write` → `docs/data/law-impact.md` | Claude Code |
| 12/1 ~ 12/31 | 지방세 관계법 개정안 국회 통과·공포 확인 (아래 2절) | 운영자 + Claude Code |
| 공포 확인 즉시 | 데이터 수정 → 빌드가 멈춘 곳 고치기 → 테스트 기대값 갱신 → `npm run check:all` → 배포 | Claude Code → 운영자 배포 |
| 12/31까지 | 개정 없음이 확인되면 확인일만 갱신 (**`evRelief.checked_at`을 12월 날짜로 — 안 하면 1월 빌드가 멈춤**, 아래 7절) | Claude Code |
| 2027-01-01 | 공개 사이트에서 계산기 3곳(취등록세·자동차세·실구매가)을 1월 날짜로 한 번씩 계산해 보기 | 운영자 |

개정 법률의 공포일과 시행일은 해마다 다르다. "통과했다"는 기사만으로 바꾸지 않고, **국가법령정보센터에서 공포된 조문**을 확인한 뒤 바꾼다(CLAUDE.md 규칙 1).

| 법령 | 확인할 조문 | 데이터 | 바뀌면 영향 |
|---|---|---|---|
| 지방세특례제한법 | 제66조 제4항(전기차 취득세 감면, 지금 2026-12-31까지 140만원) | `registration-tax/rules.json` `values.evRelief` | 1편·5편·19편, 취등록세·실구매가 계산기 |

| 지방세법 시행령 | 제125조 제6항(연납 이자율 5%), 제123조(차종 구분), 제126조(일할계산) | `car-tax/2027.json` | 같음 |
| 지방세법 | 제12조(취득세율), 제17조(면세점) | `registration-tax/rules.json` | 취득세 전부 |

국가법령정보센터에서 각 법령의 **"시행예정"** 조문과 **부칙**(시행일·적용례)을 함께 본다. 감면 연장은 보통 부칙이 아니라 해당 조문의 기한 숫자가 바뀐다.

## 3. 반영 순서

1. **데이터 수정**: 바뀐 값의 `value`, `effective_date`(시행일), `source_name`(새 법률 번호·시행일), `checked_at`을 고친다. 바뀌지 않았으면 `checked_at`만 고치고 note의 "12월 말 재확인"을 "YYYY-MM-DD 확인: 다음 해 시행 개정 없음"으로 바꾼다.
   - 감면이 연장되면서 **한도가 기간마다 달라지면** 앞 기간을 `earlier`에 남긴다. 예: `{"capWon": 700000, "until": "2027-12-31", "earlier": [{"capWon": 1400000, "until": "2026-12-31"}]}` — 이렇게 해야 12월 취득 예시가 옛 한도로 계속 맞게 계산된다.
2. **빌드**: `npm run build`. 글·도구 문장에 직접 적은 전제가 깨지면 빌드가 멈추고 고칠 파일을 알려 준다(`apps/web/src/lib/law-text-assumptions.ts`). 문장을 새 값에 맞게 고친 뒤 그 파일의 기대값을 새 값으로 바꾼다.
3. **테스트**: `npm test`. `packages/data/src/official.test.ts`의 기대값 중 실패한 것을 새 법령 조문으로 손계산해 고친다. 테스트 이름에 계산 근거를 남긴다.
4. **글 날짜**: 고친 글의 `updatedAt`(와 숫자 기준일 `asOf`)을 `apps/web/src/lib/guides.ts`에서 바꾼다.
5. **전체 점검**: `npm run check:all` → 통과하면 배포.

## 5. 시나리오별 글 처리

- **전기차 취득세 감면이 끝나면(현행법대로)**: 1편은 "감면 종료 뒤" 판을 미리 써 두었다(7절). 1월 1일 뒤 빌드하면 저절로 바뀐다. 5편·19편의 "12월에 인도받으면" 항목, 취등록세·할부 계산기의 12월·1월 비교 사례는 지난 일로 바꾸거나 뺀다(아직 손으로).
- **연장되면**: 1편 제목·결론을 "2027년에도 감면" 쪽으로 다시 쓴다. 한도가 줄면 줄어든 금액이 새 주제가 된다(새 사례 글 후보).
- **연납 공제율이 바뀌면**: 2·15·21편과 자동차세 계산기의 "5%" 문장, 2편 제목 숫자를 고친다. 1월 연납 기간 전에 끝내야 한다.

## 6. 날짜로 저절로 바뀌는 것 (손댈 필요 없음)

- 취등록세·실구매가 계산기는 취득일 기본값이 오늘이라, 1월 1일부터 현행법상 끝난 감면을 자동으로 빼고 "기한 지남"으로 보여 준다.
- 자동차세 계산기는 오늘이 속한 해의 데이터를 기본으로 고른다.
- 전기차 보조금 계산기의 BMS 폐차 재구매 지원(2026-12-31까지)은 기한이 지나면 선택지가 사라지고 계산에서도 빠진다.

## 7. 1편 "감면 종료 뒤" 판 (날짜로 바뀌는 글)

- 같은 주소 `/guides/ev-acquisition-tax-year-end/`에서, 빌드한 날(한국 시간)이 `evRelief.until`을 지나면 `content/guides/ev-acquisition-tax-after-end.tsx`와 `guides.ts`의 `afterEvReliefEnd` 제목·설명이 나온다. 숫자 기준일은 `evRelief.checked_at`.
- 안전장치(`apps/web/src/lib/guide-phase.ts`):
  - 감면이 끝났는데 `evRelief.checked_at`이 그해 12월 전이면 빌드가 **[법령 확인 필요]**로 멈춘다 — 12월 개정 확인 없이 "끝났다"고 쓰지 않기 위해.
  - 감면 종료 다음 해 12월 31일이 지나면 **[글 표현 갱신 필요]**로 멈춘다 — "작년 12월" 같은 표현이 틀려지기 때문.
- 미리 보기: `rules.json`의 `evRelief.checked_at`을 12월 날짜로 잠깐 바꾸고 `SITE_BUILD_DATE=2027-01-02 npm run build` → `npm run check:similarity`·`check:quality`. 끝나면 `rules.json`을 되돌린다.
- **감면이 연장되면** 이 판은 쓰지 않는다: `ev-relief-ends-2026` 전제가 깨져 빌드가 멈추므로, 1편 원래 판과 `afterEvReliefEnd`를 함께 다시 쓴다.
- 1월 1일 0시에 저절로 바뀌지는 않는다(정적 사이트). **1월 1일 이후 한 번 다시 빌드·배포**해야 한다.
