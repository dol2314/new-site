# 새 사이트·앱 기획안 — "전기차·내 차 돈 계산소" (가칭)

- 작성일: 2026-11-01
- 전제: **기존 사이트(bokjicard, dogmap)와 무관하게 새 도메인·새 저장소로 처음부터** 만든다.
- 실행: Claude Code. 실행 프롬프트는 [`prompts/`](./prompts/) 폴더에 순서대로 있다.
- 수익: 애드센스(웹) + AdMob(안드로이드 앱)

---

## 0. 결론 (먼저 읽을 5줄)

1. **주제: 전기차 시대의 "내 차 돈 계산"** — 전기차·하이브리드·가솔린 총비용 비교, 전기차 보조금(국비+지방비), 자동차세·연납, 취등록세, 충전·주유비. 자동차·보험 광고주가 붙는 고단가 주제이고, 차 주인 수가 많고, 매년 기준이 바뀐다.
2. **지금이 타이밍이다.** 기아 한 곳의 국내 전기차 상반기 판매가 7만 2천 대로 전년 대비 151% 늘었다(2026). 전기차를 "살까 말까" 고민하는 사람이 급증하는데, **한국 기준으로 전기차·하이브리드·가솔린 총비용을 비교해 주는 계산기는 검색에서 찾지 못했다.**
3. **AI가 대신 못 하는 페이지만 만든다.** 내 지역·내 차종·내 주행거리를 넣어야 답이 나오는 계산기, 매일 바뀌는 유가·충전요금, 지자체별 보조금 비교. 한 문단으로 끝나는 정보글은 만들지 않는다.
4. **앱은 "내 차 일정 알림"** — 정기검사 기한(지연 과태료 최대 60만 원으로 상향 보도), 자동차세(6월·12월, 연납 1월), 보험 만기, 우리 지역 보조금 공고를 먼저 알려 준다. 웹과 같은 계산 엔진을 쓴다.
5. **현실적인 기대치**: 새 도메인이라 첫 3~6개월은 검색 노출이 약하다. 1년 차 기준 시나리오는 하루 2,000명, 월 80만 원대. 첫 1월 시즌(자동차세 연납·보조금 공고)은 "색인·데이터 축적" 시즌으로 보고, 수확은 2027년 하반기~2028년 1월로 잡는다.

## 2. 새 주제 찾기 — 후보 7개 평가

### 2-1. 평가 기준 (각 1~5점, 가중 합계 55점 만점)

수요×2 + 소재 지속성 + 광고 단가×2 + AI 내성×2 + 경쟁 공백×2 + 앱 연결성 + 시기

- **앱 연결성**(이번에 추가): 알림·기록처럼 앱이어야 하는 이유가 있나. 웹·앱을 함께 만드는 조건이라 넣었다.
- 점수는 검색 결과와 판단에 기반한 값이다. 검색량·입찰가는 프롬프트 01에서 키워드 도구로 확정한다.

### 2-2. 후보 비교

| 후보 | 수요 | 지속 | 단가 | AI내성 | 공백 | 앱 | 시기 | **총점** | 메모 |
|---|---|---|---|---|---|---|---|---|---|
| **A. 전기차·내 차 돈 계산** (총비용 비교, 보조금, 자동차세, 취등록세, 충전·주유비) | 5 | 5 | 5 | 5 | 3 | 5 | 5 | **51** | 차 주인 수가 많고 전기차 판매 급증. 자동차·보험 광고. 한국형 총비용 비교 계산기 공백. 경쟁: 겟차 블로그, 카위키, 제조사 보조금 조회 |
| B. 퇴직·노후 돈 (퇴직금, IRP·연금저축 세금, 건보료 피부양자) | 4 | 4 | 5 | 5 | 2 | 2 | 3 | **41** | 고단가지만 은행·증권사가 계산기를 이미 제공. 앱 이유 약함 |

### 2-4. A의 약점과 대응

| 약점 | 대응 |
|---|---|
| 겟차(web.getcha.kr) 같은 자동차 플랫폼이 블로그 글을 대량으로 쓰고 있음 | 글 경쟁을 피하고 **계산기·데이터 비교**로 승부. 겟차 글은 "얼마 받나" 설명, 우리는 "내 조건이면 얼마, 5년 뒤 누가 이득" 계산 |
| 운영자가 자동차 전문가가 아님 (E-E-A-T) | 모든 계산의 **산식·가정·출처를 공개**하는 "계산 방법" 섹션, 데이터 기준일 표시, 오류 제보 창구. 운영자가 직접 차를 운용한 기록(실제 주유·충전비)을 사례로 쓰면 가장 좋음 |
| 전기차 보조금 지방비 데이터: 공식 API를 찾지 못함 | 무공해차 통합누리집 공개 표·지자체 공고를 **이용약관·robots 확인 후** 수집, 안 되면 주 1회 수동 갱신 + 출처 링크. 잔여 대수 실시간 표시는 허용될 때만 |
| 2027 보조금·연납 할인율이 아직 미확정 | 2026 값으로 구조를 먼저 만들고 "2027 발표 예정" 배지, 발표 당일 데이터만 교체 |

후보: **차값계산소**(chacalc), **전기차계산기**(evcalc), **드라이브머니**(drivemoney). `.kr`/`.co.kr`/`.com` 등록 가능 여부는 운영자가 확인한다. 기준: 짧고, 한글 이름을 영문 도메인으로 바로 떠올릴 수 있고, "전기차"에만 갇히지 않는 이름(내연기관 차 주인도 오게).

### 3-3. 페이지 하나가 갖춰야 할 것 (승인·스팸 방어)

모든 도구 페이지는 아래를 **전부** 갖춰야 공개한다.

1. 계산기 (입력값은 브라우저 밖으로 보내지 않음)
2. 첫 3문장 요약 — AI 개요·네이버 AI 브리핑이 인용하기 좋은 결론형 문장
3. **실제 차종 사례 3개 이상** (예: 아이오닉5 vs 투싼 하이브리드 vs 투싼 가솔린, 연 1.5만 km) — 숫자는 엔진으로 계산
4. **계산 방법** 섹션 — 산식, 가정값(유가·전기요금·정비비), 출처, 기준일
5. 기준표 (세율·보조금 등)
6. FAQ 5개 이상
7. 다음에 할 일 — 관련 도구 2~3개, 공식 신청·조회 링크
8. 면책 문구, 데이터 기준일, 검수일

### 3-4. 해설 글 (주 3편 상한)

- 형식: **"특정 차 + 특정 조건 + 숫자" 사례 분석**. 예) "연 2만 km 출퇴근, 아이오닉5와 투싼 하이브리드 5년 비용 차이는?", "서울과 전남, 같은 EV3 보조금 차이 얼마?"
- 사례마다 계산기 결과를 표로 붙이고, 조건을 바꾼 변형 2개 이상.
- 차종×지역 조합을 자동으로 찍어내지 않는다. 사람이 고른 조합만, 검수 후 공개.
- 애드센스 신청 전 목표: 도구 5개 + 글 20편.

## 4. 앱 기획 — "내 차 일정" (가칭) 안드로이드 앱

### 4-1. 앱이어야 하는 이유

웹 계산기는 차 살 때 한 번 쓰고 끝난다. 차를 산 뒤에는 **놓치면 돈이 나가는 날짜**가 반복된다: 정기검사(지연 과태료), 자동차세 6월·12월, 연납 1월, 보험 만기, 보조금 공고(차 사기 전). 이건 앱 알림이 가장 확실하다.

### 4-2. MVP 기능

1. **내 차 등록 (기기 안에만 저장)**: 차종(연료), 배기량, 최초등록일, 보험 만기일, 시도·시군구
2. **일정 자동 생성 + 로컬 알림**: 검사 기간(시작·마감 전), 자동차세 납기(6/16~30, 12/16~31), 연납 기간(1월), 보험 만기 30일·7일 전
3. **보조금 공고 알림** (차 사기 전 사용자): 우리 지역 공고·잔여 현황 변화 시 (웹이 공개하는 JSON을 하루 1회 확인)
4. **계산기**: 웹과 같은 엔진 (총비용 비교, 자동차세, 충전·주유비)
5. **주유·충전 기록 (선택)**: 월 비용 그래프 — 기록이 쌓이면 지우기 어려워 이탈 방지
6. 오프라인 동작

### 4-3. 기술

- Capacitor + React(Vite) + TypeScript, 웹과 계산 엔진 공유 (`packages/calc-core`)
- 플러그인: 로컬 알림, 기기 저장(Preferences), AdMob
- 웹사이트를 그대로 감싸는 TWA는 쓰지 않는다 (앱만의 기능이 없으면 Play "최소 기능" 정책 위험)

### 4-4. 수익화 (AdMob)

- 홈·일정 하단 배너 1개, 기록 목록 사이 네이티브 광고
- 전면 광고 없음 (실행 직후·뒤로 가기·계산 결과 앞 금지)
- 앱 단독 수익은 작게 본다(월 수만 원대에서 시작). 진짜 가치는 재방문과 웹 유입.

### 4-5. Play 출시 체크

- 2023-11 이후 만든 개인 개발자 계정: 프로덕션 출시 전 **비공개 테스트 12명 이상, 14일 연속**
- 타깃 API: 2026-08-31 이후 신규 앱·업데이트는 Android 16(API 36) 이상으로 알려짐 — 출시 시 Play Console 공지로 재확인
- 정부 정보(세금·보조금) 제공 앱: 정부 기관과 무관함을 명시하고 정보 출처 URL 표시
- 데이터 보안 섹션: 기기 내 저장, AdMob 광고 ID 수집 명시

## 6. 수익 추정 (가정 명시)

**월 수익 = 일 방문 × 방문당 PV × 30 × (페이지 RPM ÷ 1,000)**

가정: 방문당 PV 2.0, 페이지 RPM 보수 4,000원 / 기준 7,000원 / 낙관 10,000원 (자동차·보험 광고, 새 사이트 할인 반영. 실측 전 가정값). 새 도메인이라 첫 3~6개월은 검색 노출이 약하다.

| 시점 | 일 방문 (보수 / 기준 / 낙관) | 월 웹 수익 (기준) | 비고 |
|---|---|---|---|
| 2027-01 | 30 / 150 / 400 | 약 6만 원 | 연납·보조금 시즌이지만 색인 초기. 애드센스 승인 전일 수 있음 |
| 2027-03 | 100 / 400 / 1,000 | 약 17만 원 | 보조금 시즌, 네이버 블로그·커뮤니티 유입 |
| 2027-06 | 300 / 900 / 2,000 | 약 38만 원 | 자동차세 1기 |
| 2027-10 (12개월) | 600 / 2,000 / 4,000 | 약 84만 원 | |
| 2028-01 (두 번째 시즌) | 1,500 / 5,000 / 10,000 | 약 210만 원 | 시즌 피크 한 달 |
| 앱 (12개월, MAU 3,000~8,000 가정) | — | 월 3~15만 원 | 재방문·웹 유입 효과 별도 |

8주차와 6개월 차에 서치콘솔·애드센스 실측으로 이 표를 다시 계산한다 (프롬프트 12).

## 9. Claude Code로 실행하는 방법

1. GitHub에 **새 저장소**를 만든다(예: `dol2314/chacalc`, 이름은 01 결과로 결정). 그 저장소를 연 Claude Code 세션에 아래 **시작 프롬프트**를 붙여 넣는다.

   ```
   공개 저장소 https://github.com/dol2314/agency 의 브랜치 claude/clever-clarke-v5sxgh 에서
   plans/new-site-2027/ 폴더를 임시 폴더에 git clone --depth 1 로 받아,
   - plans/new-site-2027/README.md → docs/plan/README.md
   - plans/new-site-2027/prompts/ → docs/plan/prompts/
   - docs/plan/prompts/00-CLAUDE.md 의 "# CLAUDE.md" 이하 내용 → 루트 CLAUDE.md
   로 복사하고 커밋하라. 복사한 파일 목록을 보여 주고, 푸시 전에 확인을 받아라.
   ```
2. 이후 `docs/plan/prompts/`의 프롬프트를 **번호 순서대로, 한 세션에 하나씩** 실행한다. 각 파일의 "Claude Code에게" 블록을 붙여 넣으면 된다.
3. 각 프롬프트의 "완료 조건"을 Claude Code가 실제로 확인해 보고한다. `verified: false` 값이 있으면 그 화면은 공개되지 않는다.
4. 사람이 할 일(도메인 구매, 키워드 도구 내보내기, API 키 발급, Cloudflare·서치콘솔·애드센스·AdMob·Play Console, 테스터 모집, 글 검수)은 각 프롬프트의 "운영자 작업"에 있다.
