# 프롬프트 02 — 저장소·사이트 뼈대

## 운영자 작업 (먼저)
- 도메인 구매, Cloudflare에 도메인 연결
- GA4 속성 생성(측정 ID), 이후 애드센스 계정(기존 계정 사용 가능)

## Claude Code에게
```
docs/plan/README.md 3-5절(정보 구조)과 CLAUDE.md를 읽어라.

1. 모노레포 구성: npm workspaces(또는 pnpm, 저장소에 이미 있으면 그것). apps/web, apps/mobile(빈 자리), packages/calc-core, packages/data, scripts/.
   각 의존성은 현재 안정 버전을 확인해 고정한다.
2. apps/web: Next.js App Router, 정적 출력(output: 'export'), trailingSlash: true, Cloudflare Pages 배포. TypeScript strict. 스타일은 Tailwind 또는 CSS Modules 중 하나로 단순하게.
3. 공통 레이아웃: 헤더(도구 메뉴), 푸터(about/contact/privacy/terms/data), 모바일 우선, 큰 글씨, 다크모드.
4. 페이지 자리: 3-5절의 모든 URL. 아직 내용이 없는 페이지는 만들지 마라(빈 페이지·"준비 중" 페이지는 애드센스 반려 사유). 홈·about·contact·privacy·terms·data만 먼저 실제 내용으로 만든다.
   - about: 운영자 소개 자리(운영자에게 내용 요청, 지어내지 마라), 사이트 원칙(공식 출처, 계산 방법 공개, 입력값 비저장), 오류 제보 방법
   - privacy: GA4·애드센스 쿠키·광고 ID 고지, 입력값 비전송 명시
   - data: 데이터 출처 표(기획안 3-6절)와 갱신 기록 자리
5. SEO 기반: metadataBase, 페이지별 title·description·canonical·og(공통 og 이미지 생성), JSON-LD(WebSite, Organization, 페이지별 BreadcrumbList), sitemap.xml·robots.txt·rss.xml 빌드 시 생성, 한국어 404 페이지(noindex 하나만), ads.txt 자리(값은 운영자 확인 후).
6. Cloudflare Pages: public/_headers 로 정적 자산 1년 캐시, 보안 헤더. http→https·www 처리 방법은 운영자 단계로.
7. GA4: 동의 없이도 동작하는 기본 설정 + 이벤트 헬퍼 track(name, params) — params에 사용자 입력값이 들어가지 않게 타입으로 막아라.
8. CI: GitHub Actions에서 lint, typecheck, test, build.
9. scripts/check-seo.mjs: 빌드 결과 HTML에서 title·description·canonical·og:image 고유성, h1 1개, noindex 중복을 검사.
10. 빌드·검사 결과와 운영자 할 일(Cloudflare Pages 연결, 서치콘솔 도메인 속성, 네이버 서치어드바이저, Bing 등록)을 보고하라.
```
